# 教学缺口与执行验证

Teach Mode 将录制完整性与业务教学覆盖分别检查。录制完整、文件成功保存，并不代表每个业务步骤都已被示范，也不代表生成的技能已经能够独立完成任务。

生成技能时，Skill Creator 逐步核对录制，区分实际观察到的动作、仅有相关页面的上下文、用户补充的要求和尚未确认的步骤。缺少日期填写、下拉选择、读取字段或结果确认时，应明确列出缺失内容、影响的步骤，以及补充示范或验证实际结果的下一步。用户已经给出的参数无需重复询问，也无需伪造一次澄清确认；这些补充也不会改变原始录制是否完整。

技能可以带着已说明的缺口保存。对话中的保存结果和生成的 SKILL.md 都包含缺口说明；references/teaching-gaps.json 保留对应步骤及证据分类，供新对话调用时检查。没有声明具体缺口也不等于已经证明教学完整，执行状态仍为 not_run。

结构检查会拒绝把附近的导航、点击当作日期值填写或下拉选项变化的证据。具体任务的语义覆盖仍由 Skill Creator 对照用户要求和完整事件记录进行判断，不能声称系统能够自动发现所有遗漏。

开发验证包括：上下文证据与真实动作的区分、未录制步骤的保留、用户补充要求的来源、日期/选择动作证据校验、缺口文件发布与原录制完整性不变。业务验收仍需在新的 Memmy 对话中使用新参数执行，并独立核对页面结果、输出文件或提交回执。
